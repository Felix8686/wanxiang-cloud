IMPORTANT FIX: WAITUNTIL -> CLOUDFLARE QUEUE

The first real receipt reached D1 but remained status=processing because the old implementation ran Vision inside HTTP ctx.waitUntil(). Cloudflare cancels HTTP waitUntil work after 30 seconds after the response ends. Vision can exceed that window, leaving the processing marker without a terminal update.

The branch now uses:

Telegram webhook
-> enqueue wanxiang-receipt-dev
-> immediate Telegram acknowledgement
-> Cloudflare Queue consumer
-> Telegram getFile/download
-> Workers AI Vision
-> validation/reconciliation
-> D1 transaction + transaction_items
-> final Telegram reply

Queue consumer jobs have a much longer execution window than HTTP waitUntil. The code also adds:
- 30 second Telegram download timeout;
- 120 second Vision timeout;
- failed/rejected terminal status on timeout/error;
- stale processing recovery after 240 seconds;
- ownership check before D1 write;
- retrying the same photo after a failed/stale attempt without duplicate transaction creation.
