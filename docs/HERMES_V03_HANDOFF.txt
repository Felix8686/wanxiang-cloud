ISOLATED VALIDATION

Use controlled fixtures before asking the user for a real receipt.
Do not use the user's real receipt as the first test.

Required cases:

1. Existing text Telegram path
Input: 晚饭25元，支付宝
Expected: legacy flow still works.
Clean up only the exact synthetic test transaction afterward.

2. Existing query path
Input: 今天花了多少
Expected: legacy query still works and creates no transaction.

3. Clear receipt image
Expected:
- Telegram getFile/download succeeds;
- Vision returns is_receipt=true;
- transaction + transaction_items written;
- item/category values plausible;
- amount reconciliation passes.

4. Multi-category receipt
Expected different item categories, not one category for the entire receipt.

5. Amount mismatch fixture
Expected no transaction write and a Telegram failure message.

6. Non-receipt image
Expected no transaction write.

7. Duplicate photo
Send/replay the same Telegram file_unique_id.
Expected no duplicate transaction.

8. Large/invalid image/download failure
Expected safe failure, no transaction.

9. Privacy
Confirm no receipt image object appears in R2 and no file URL/token is stored in D1/Git/log output.

After isolated testing, remove only clearly identified synthetic test transactions/items/ingestion fixtures. Do not touch real user data.

REAL TELEGRAM E2E

Only after all isolated validation passes, ask the user to send one real supermarket receipt photo from their Telegram client.

Validate the real chain:
Telegram photo
-> webhook 200/accepted
-> Telegram getFile
-> image download
-> Workers AI Vision
-> structured receipt
-> reconciliation
-> transactions + transaction_items
-> Telegram summary reply

The user's real receipt is real accounting data. Do NOT delete it unless explicitly instructed.
