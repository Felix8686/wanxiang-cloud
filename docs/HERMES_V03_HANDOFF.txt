CURRENT ARCHITECTURE

Telegram photo
-> /telegram/webhook
-> Cloudflare Queue wanxiang-receipt-dev
-> Queue consumer
-> Telegram getFile/download
-> Workers AI Vision
-> validation/reconciliation
-> D1 transactions + transaction_items
-> final Telegram reply

Files:
- src/app.ts: HTTP + Queue entry
- src/receipt-job.ts: Queue job / locking / timeout / persistence
- src/receipt.ts: Vision request / structured-output extraction / reconciliation
- src/index.ts: legacy text/API path

LATEST CHATGPT FIX

The latest code specifically fixes Workers AI Vision/structured-output compatibility:

1. Image data is sent through the native top-level `image` field to env.AI.run().
2. messages contain textual instructions only.
3. response_format remains json_schema.
4. Gemma thinking is disabled with chat_template_kwargs.enable_thinking=false.
5. max_completion_tokens is used.
6. extractJsonValue() now supports:
   - choices[0].message.parsed
   - response object
   - response JSON string
   - choices[0].message.content string
   - array text content
   - nested result wrapper
   - direct parsed receipt object
7. Unknown AI response structures emit only:

receipt AI response shape {...}

The diagnostic contains only types, key names and counts. It MUST NOT contain OCR text, response content, image bytes/data URI, Telegram file path, Bot Token or Secret.
